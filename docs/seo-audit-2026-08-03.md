## 对四个直接问题的结论

### 1. Chrome 为什么显示 Not Secure？

**根因已经隔离：不是 `geoqiao.me` 主证书或站点 mixed content，而是当前 Chrome 配置中的 Immersive Translate 扩展。**

证据：

1. 主文档使用 TLS 1.3，证书对 `geoqiao.me`/`www.geoqiao.me` 有效；GitHub Pages API 显示 HTTPS 已强制执行。
2. Chrome CDP 对页面复现了 `securityState=insecure-broken`，唯一问题码为 `ran-content-with-cert-error`；这解释了“Certificate is valid”与“Not Secure”同时出现。
3. 生产页面没有 HTTP 资源、HTTP form 或 mixed-content 控制台错误；干净浏览器显示 secure context。
4. 仅屏蔽扩展 `bpoadfkcbjbfhfodiogcnhhhpibjhbnh` 的 `content_main.js` 后，同一 Chrome、同一页面立即变为 `securityState=secure`。
5. 本机扩展 manifest 将该 ID 标识为 **Immersive Translate: AI Web, PDF & Video Translator**。

处理建议：在 Chrome 中暂停该扩展对 `geoqiao.me` 的 Site access，或更新/禁用扩展后重新打开页面。**不建议为此修改站点 TLS、DNS 或代码。**

### 2. 亮暗主题是否跟随系统？

**会，但仅在用户没有手动选择主题时。**

`src/escaping/themes/geoqiao.me/static/js/theme.js` 的行为是：

- 无 `localStorage.theme`：读取 `prefers-color-scheme`，并监听系统主题变化；
- 用户点击主题按钮后：保存 `light`/`dark`，以后优先使用手动选择，不再跟随系统；
- Utterances 在 `comments.theme_mode=auto` 时通过 `MutationObserver` 跟随站点 `data-theme`。

当前没有可见的“恢复 Auto”入口。如需要三态体验，应单独实现 `auto / light / dark`，而不是改变现有用户偏好的语义。

### 3. 是否满足 GSC 与 Google 收录条件？

**满足基本抓取与索引资格，但尚未完成 GSC 所有权验证，而且公开 Google `site:` 查询当前没有发现已收录结果。**

已满足：

- Googlebot 请求首页、robots、sitemap、代表文章均返回 `200`；
- `robots.txt` 允许抓取并声明 sitemap；
- sitemap 有 68 个绝对 HTTPS URL，68/68 返回 `200` 且 self-canonical 一致；
- 正文是服务端生成的静态 HTML，不依赖 JavaScript 才出现；
- 没有 `noindex`；HTTP、`www`、`geoqiao.github.io` 均归一到 HTTPS 主域；
- Google Rich Results Test 成功抓取代表文章，检测到 1 个有效 Article。

尚未完成或未知：

- Browser Harness 中的当前 Google 账号对 `https://geoqiao.me/` property 显示 **未验证/无访问权**；
- 首页已有 meta verification token，可用于对应账号的 URL-prefix property，但不能证明当前账号已拥有 property；
- apex DNS 没有 `google-site-verification` TXT，因此尚不能据此证明 Domain property；
- `site:geoqiao.me` 与 `site:geoqiao.github.io` 的公开查询均返回“没有匹配文档”；该运算符不是完整索引报告，最终以 GSC URL Inspection/Page indexing 为准；
- sitemap 尚未在已验证 property 的 Sitemaps report 中确认 `Success`。

推荐使用 **Domain property `geoqiao.me` + DNS TXT**，然后提交 `https://geoqiao.me/sitemap.xml`，对首页、Blog index、最新文章和一篇历史文章执行 URL Inspection。满足技术条件不等于 Google 保证收录或排名。

## 一、结论摘要

站点当前具备良好的基础可抓取性：HTTPS、状态码、robots、sitemap、canonical、静态正文、移动适配和 JSON-LD 基线都有效。Google Rich Results Test 证明代表文章具备 Article rich-result 资格。

阻碍自然搜索增长的主要问题不是“Google 无法读取页面”，而是：

1. **迁移安全缺口**：旧 sitemap 的 91 个 URL 中 89 个现在为 404；
2. **测量缺口**：GSC 尚未验证，无法确认索引、查询、CTR、衰退或迁移损失；
3. **移动性能缺口**：首页移动 LCP 5.1s，代表文章移动 LCP 17.4s；
4. **搜索摘要与内容架构缺口**：33 页空 description、34 篇文章没有一个有效正文内链、17 个单文章 Tag 页面；
5. **转化闭环缺口**：未定义核心转化，也没有站内分析或来源快照。

## 五、转化路径与执行动作

当前可观察路径只能到搜索点击：

```text
Google query → landing page → 标签/导航/外链
```

目标闭环必须先选择一种核心转化：

```text
Google query
→ landing page
→ related content / contextual CTA
→ RSS subscribe | GitHub visit/use | contact
→ conversion event
```

若选择埋点，应先定义隐私口径，再选择 GA4、隐私友好分析或不采集个人数据的方案。当前站点没有 GA4/其他 analytics，GitHub Pages 也不向站点提供可用的原始访问日志，因此不能构造转化归因数字。

## 六、低风险执行顺序

1. **不改页面先建立基线**：验证 GSC、提交 sitemap、保存索引/URL Inspection/性能快照。
2. **迁移保护**：建立旧 URL→新 URL 映射，先处理旧 Blog/About，再处理有价值 Tag；只做 additive compatibility，不改新 canonical。
3. **元数据快速修复**：全站描述、分页唯一标题/描述；不改 URL。
4. **性能快速修复**：本地优化 avatar；压缩 Issue #41 首图；按需加载 Prism/Mermaid。
5. **rich-result 增强**：Article `image`、`author.url`、BreadcrumbList。
6. **内容小批修复**：每批 3–5 页处理描述、失效链接、嵌套 Markdown、H1、上下文内链。
7. **取得至少 28 天数据后**：决定空 Ideas/Projects 和单文章 Tag 的 index 策略。

分类：

- **低风险快速优化**：GSC、站点 description、分页标题、avatar 优化、按需 Prism、JSON-LD 可选字段。
- **需要观察的内容调整**：文章 description、内链、alt、失效链接、可见作者/更新时间。
- **高风险技术改造**：批量 noindex、删除页面、改变 canonical/URL、边缘 301/CDN 迁移。

## 七、预计影响与风险

- GSC 与 sitemap 提供测量和发现能力，**不保证收录或排名**。
- 旧 URL compatibility 可保护潜在历史信号，但错误映射会造成软 404/重复内容。
- 图片压缩有明确的字节与 LCP 改善空间，但需保护清晰度与首屏加载优先级。
- description 更改主要影响摘要与 CTR 机会，不应声称直接提升排名。
- thin Tag/noindex 的收益高度依赖 GSC 数据，当前不能确定。
- 转化优化必须等核心转化与隐私边界确定，否则“增长”没有可核对的终点。
